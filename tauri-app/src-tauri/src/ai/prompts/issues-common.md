# Общие проблемы всех режимов — план решения

Общие инфраструктурные/промптовые проблемы, влияющие на все режимы
(Project, Maintenance, Cli, Planning). Детали по режимам — в соответствующих
`issues-*.md`. Источники: разбор сессий 2026-08-08 (EPF) и 2026-08-09 (Planning).

## Детали и план по каждой

### MCP-1. Кодировка и кавычки в `run_command` (P1)

**Симптомы** (сессия EPF):
- Кириллица в выводе PowerShell ломается.
- Кавычки `"` в аргументах превращаются в `\"` → файл повреждался; агент придумал
  плейсхолдер `~q~` → `[char]34` и вручную ставил `[Console]::OutputEncoding = UTF8`.

**План**:
- В `mcp-1c-filesystem/src/run_command`: перед запуском PS задавать
  `[Console]::OutputEncoding = [System.Text.Encoding]::UTF8` (или флаг `-EncodedCommand`).
- Читать stdout/stderr как UTF-8.
- Экранировать аргументы без `\"` (передавать через массив args, а не строку).
- Добавить тест на кириллицу (run_command с `Write-Host 'Привет'` → ожидать UTF8).

### MCP-2. Запрет `run_command`/записи в Planning (P0)

**Симптомы** (сессия Planning): `ibcmd infobase config save/check`, `eventlog read`,
`Get-Process` — все в read-only режиме.

**План**:
- Промпт: в `PLANNING_READONLY_RULES` добавить явный список запрещённых
  инструментов (`run_command`, `write_file`, `edit_file`, `delete_file`,
  `create_directory`) и список разрешённых (поиск/метаданные).
- Сервер: в Planning-сессии `mcp-1c-filesystem` возвращать ошибку на
  записывающие/исполняющие инструменты (флаг режима в конфиге сессии).

### MCP-3. 1С-скиллы не в `mcp-1c-skills` (P0)

**Симптомы** (сессия EPF): `search_skills` пуст → агент без готовых скриптов
`epf-init`/`epf-build`/`epf-full-cycle`, собирал EPF вручную.

**План**:
- Подключить 1С-скиллы к серверу скиллов: источник `config/skills/`
  (в т.ч. worktree `worktrees/config-skills/config/skills/`) + существующие
  dev-скиллы `.agents/skills/`.
- Согласовать категории: `1c-skills`, `bsp`, `dev` (агент-скиллы).
- Обновить `ensure_builtin_mcp_servers` / путь загрузки в Rust-сервере.

### MCP-4. Спутанные ID скиллов/документов (P2)

**Симптомы**: `get_skill("epf-guide")` — а это документ; `get_doc` на скилл.

**План**:
- В ответах `list_skills`/`list_docs`/`search_*` маркировать категорию префиксом:
  `[skill] ...`, `[doc] ...`, `[rule] ...`.
- В `get_skill`/`get_doc` возвращать ошибку, если ID принадлежит другому типу.
- В описаниях инструментов уточнить: «ID должен совпадать с типом инструмента».

### MCP-5. Семантический поиск скиллов/документов (P2)

**Симптомы**: `search_skills` ищет только по названию/описанию (точное совпадение).

**План** (долгосрочный, как отметил пользователь):
- Векторный/семантический поиск по контенту SKILL.md (эмбеддинги или BM25+fuzzy).
- Аналогично для документов и правил. Возможно — RAG/wiki поверх `config/docs`.

### MCP-6. Пустой sandbox (P2)

**Симптомы**: `list_directory` пуст → ручное создание структуры EPF.

**План**:
- Инициализировать workspace перед сессией (шаблон EPF/исходники, `.v8-project.json`).
- Либо описать в промпте: «если песочница пуста — сначала вызови скилл инициализации».

### PROMPT-1. Дрейф в рефакторинг вместо задачи (P1)

**Симптомы**: агент исправил чужой модуль (тире, пустой блок, `КлючСтрокой`) и
прогнал диагностику до чистоты, но EPF не создал.

**План**:
- Во все режимы разработки добавить: «Сначала заверши запрошенное. Найденные
  проблемы перечисли отдельным блоком, но не исправляй, если это не входит в запрос».
- В Maintenance — запрет уже есть (STRICT COMPLIANCE); добавить «баги только списком».

### PROMPT-2. Приоритет скриптов скиллов (P1)

**Симптомы**: агент искал OneScript, хотя в скиллах были PowerShell-скрипты.

**План**:
- В промпт: «Если для задачи есть скрипт в скилле (.ps1/.py) — используй его
  в первую очередь, документацию — для проверки/уточнения».
