# Режим «Планирование» (Planning) — проблемы и план

> Режим: архитектор 1С, исследует конфигурацию, составляет ПЛАН изменений.
> НЕ вносит изменения в код — только анализ. Read-only.

## Зафиксированные проблемы (сессия 15:18–15:20, ошибки запуска ERP)

Источники: `review.txt`, `reasoning.txt`, `mini-ai-1c-logs.txt` (2026-08-09).
Задача: составить план решения двух ошибок:
1. «Недопустимое обращение к необновленным параметрам работы программы».
2. «Длина ключа индекса превышает максимально допустимую».

### P0. `run_command` в read-only режиме
- Агент выполнял `run_command` с `ibcmd.exe` напрямую к базе `E:\1cBase\ERP`:
  - `ibcmd infobase config --help`
  - `ibcmd infobase config save --db-path=E:\1cBase\ERP --file=E:\workspace\ERP_save.cf`
  - `ibcmd infobase config check --db-path=E:\1cBase\ERP`
  - `ibcmd eventlog read --db-path=E:\1cBase\ERP`
  - `Get-Process | Where 1cv8|ibcmd|ragent`
- **Проблема**: промпт говорит «read-only», но НЕ запрещает `run_command`.
  Сам агент в reasoning зафиксировал «режим планирования — только анализ, без
  изменений кода», но счёл `run_command` легитимным способом исследования.
- **Решение**:
  - В `PLANNING_READONLY_RULES` добавить явный запрет: `run_command`, `write_file`,
    `edit_file`, `delete_file`, `create_directory` — запрещены.
  - Список разрешённых инструментов: только поиск/метаданные
    (`semantic_find`, `search_code`, `get_object_structure`, `get_skill`, `get_doc`, `search_1c_help`).
  - На уровне `mcp-1c-filesystem`/`mcp-1c-search`: в Planning-сессии сервер может
    возвращать ошибку на записывающие/исполняющие инструменты (защита от дрейфа).

### P1. Попытка выгрузить конфигурацию/данные базы
- `ibcmd infobase config save --db-path=E:\1cBase\ERP --file=E:\workspace\ERP_save.cf`
  — попытка выгрузить `.cf` боевой конфигурации (остановлена блокировкой базы).
- `ibcmd infobase config check`, `eventlog read` — чтение боевой базы.
- **Решение**: прямое взаимодействие с базой через `run_command` запретить в
  промпте. Исследование — только через проиндексированный профиль `mcp-1c-search`.

### P2. Игнорирование поискового профиля
- Профиль поиска с базой ERP уже был настроен, но агент пошёл в `ibcmd` вместо
  `get_object_structure` / `semantic_find` / `search_code`.
- **Решение**: в промпт Planning инжектить блок «Конфигурация проиндексирована в
  mcp-1c-search — используй инструменты поиска. НЕ обращайся к базе напрямую».

### P3. Reasoning drift в синтаксис ibcmd
- ~40% reasoning (строки 478–1208) ушло на разбор синтаксиса `ibcmd`, обход
  дедупликации вывода, кодировки. Ничего не дало.
- **Решение**: запрет `run_command` + явная подсказка об инструментах поиска
  устранят дрейф.
