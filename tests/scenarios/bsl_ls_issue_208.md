# Сценарий: BSL Language Server 1.x, MCP и восстановление #208

## Предусловия

- Windows.
- Mini AI 1C запущен в debug-режиме.
- Доступ к GitHub Releases.
- В настройках выбран тестовый BSL workspace с `.bsl`-файлом.

## Шаги

1. Открыть `Настройки → BSL Language Server`.
2. Нажать `Download` и дождаться завершения.
3. Проверить:
   - версия сервера — актуальный GitHub Release;
   - runtime — встроенный;
   - LSP — `Online`;
   - Official MCP — `Доступен`.
4. Проверить, что в пользовательских настройках отсутствуют ручные блоки `Legacy JAR` и `BSL Workspace`, а `WebSocket Port` доступен.
5. Запустить встроенную диагностику. Все проверки native launcher, LSP и MCP должны быть `ok`.
6. Выполнить три последовательных вызова `check_bsl_syntax` для кода с известной синтаксической ошибкой.
7. Убедиться, что каждый вызов вернул diagnostics без `Timeout waiting for BSL LS response`.
8. Принудительно завершить только дочерний процесс BSL Language Server.
9. Повторить `check_bsl_syntax`.
10. Убедиться по логу, что соединение инвалидировано, сервер запущен/подключён повторно и анализ выполнен после одной повторной попытки.
11. Обновить список инструментов `bsl-ls` и проверить наличие внутренних и официальных инструментов.
12. Вызвать официальный `analyze_file` для `.bsl`-файла внутри workspace.
13. Отправить в чат запрос: «Проверь этот BSL-код через BSL Language Server и перечисли синтаксические ошибки», приложив ошибочный код.
14. Проверить в логе вызов `check_bsl_syntax` и содержательный ответ чата.

## Ожидаемый результат

- Установка выполняется из официального Windows asset с проверкой SHA-256.
- Внешняя Java не требуется.
- Ручной блок `Legacy JAR` не отображается в актуальных пользовательских настройках.
- Ручной блок `BSL Workspace` не отображается; приложение использует служебный workspace автоматически.
- `check_bsl_syntax` не зависает на 15-секундном timeout.
- После разрыва выполняется одно автоматическое восстановление.
- В чате доступны 3 внутренних и upstream MCP-инструменты текущего сервера.
- Файловые upstream-инструменты работают внутри зарегистрированного workspace.
